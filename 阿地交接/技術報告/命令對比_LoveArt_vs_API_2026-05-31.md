# 🪷 為什麼同引擎出圖不同？LoveArt 阿美 vs 直接 API 命令對比

> 阿地 6 號 2026-05-31 給阿元。引擎都是 Nano Banana Pro，但兩批命令結構不同 + 平台多包一層。**故事內容不列入比較，只比生成命令機制。**

---

## ⚡ 一句話結論

**兩個原因疊加：**
1. **命令本身不同**（最大差異 = 參考圖怎麼餵）
2. **平台多包一層**（LoveArt 不是裸 API，它會自己改寫 prompt + 加系統指令 + 自己的預設參數）

→ 所以**不是純平台不同，命令也真的不一樣**。要做公平實驗，必須兩邊餵「同一句 + 同一張真圖」。

---

## 📊 命令機制對照表（不含故事）

| 比較項 | LoveArt 阿美妹妹 (v8/v10) | 直接 Gemini API (daemon) |
|---|---|---|
| **引擎** | Nano Banana Pro | gemini-3-pro-image-preview（=同引擎）|
| **參考圖怎麼餵** | 文字寫 LoveArt **網址** `https://a.lovart.ai/...` | 送**真實 PNG 像素** `ref_images:["8-05.png"]` |
| → 模型真的看得到圖？ | **不一定**（要平台把 URL 還原成圖輸入，否則只是文字）| **是**（直接讀像素）|
| **參考圖數量** | 一次塞 **12 個**角色卡 URL | 通常 **1 張**主 ref |
| **prompt 語言** | 中文 | 英文風格前綴 + 中文場景 |
| **prompt 長度** | 很長（強制複製清單+禁止清單）| 精簡（前綴+場景+Copy清單）|
| **鎖造型寫法** | 「強制複製 URL... + Image #N」 | 英文 `Copy EXACTLY: face/crown/staff...` |
| **負面提示** | 大量「禁：❌光頭❌橙袈裟...」 | 較少 |
| **平台前處理** | ✅ LoveArt 會**自己改寫/擴寫** prompt、加系統指令、套自家比例/取樣預設 | ❌ 只有你送的 prompt + ref + config，無額外包裝 |

## 🔬 三個真正影響出圖的差異（排序）

### ① 參考圖機制（影響最大）★★★★★
- **API**：8-05.png 像素直接進模型 → 臉/五瓣冠/9環錫杖被強力複製。
- **LoveArt**：給的是網址文字。**12 個 URL 一次塞**，平台若沒全部當圖輸入，模型只收到「強制複製 URL:xxx」這種**它看不懂的文字** → 造型只能靠後面中文描述硬湊 → 偏移。
- 👉 這就是「同名字命令，出來不一樣」最可能的元兇。

### ② 平台包裝層（影響大）★★★★
LoveArt **不是裸 Nano Banana Pro**，是一層 agent：
- 會把你的 prompt **重寫/擴寫**（阿美常「先描述再問」就是這層在運作）
- 注入自己的**系統指令**（風格、安全、格式）
- 套自家的**解析度/比例/seed/取樣**預設
→ 就算你貼一模一樣的句子，輸出也會被這層改變。
直接 API = 你送什麼就是什麼，沒有中間人。

### ③ prompt 語言與長度（影響中）★★★
- LoveArt 超長中文 + 大量禁止清單 → 重點被稀釋，模型抓重點能力下降。
- API 精簡英文前綴 → 風格指令更集中、更穩。
- 研究記錄：5 號發現「prompt 越長越差」（`★★★★★研究報告_為什麼越長越差_2026-05-28.md`）。

## 🧪 想做「公平實驗」該怎麼控制變因

要分辨到底是「命令差」還是「平台差」，建議：

1. **同一張 ref 圖**：兩邊都用 8-05.png（API 用 ref_images；LoveArt 上傳同一張，不要用一堆 URL）。
2. **同一句 prompt**：用最精簡的英文 Copy 清單 + 一句場景，兩邊貼一模一樣的。
3. **只放 1 張參考**：不要塞 12 個角色卡。
4. 比對結果：
   - 若還是差很多 → **平台包裝層**是主因（LoveArt 改寫了你的 prompt）。
   - 若變接近 → 之前的差異主要來自**命令結構**（URL文字 vs 真圖、長度、禁止清單）。

---

## 📌 我的判斷

最可能：**①參考圖機制 + ②平台包裝** 兩者合起來造成你看到的差距，
**不是純平台不同**。命令結構（尤其 ref 圖是「網址文字」還是「真實像素」）才是主因。
