- **Playwright config:** 已加 `--allow-unrestricted-file-access` flag

## 操作流程(Playwright MCP)

```js
// Step 1 navigate
mcp__playwright__browser_navigate
  url: https://business.facebook.com/latest/posts/published_posts/?asset_id=1093357677358320

// Step 2 點建立貼文
mcp__playwright__browser_evaluate function=`
  const btn = Array.from(document.querySelectorAll('div, button, [role="button"]'))
    .filter(b => b.offsetParent)
    .find(b => /^建立貼文$/.test((b.textContent||'').trim()));
  btn.click();
`

// Step 3 強制 input multiple + 點新增相片
mcp__playwright__browser_evaluate function=`
  document.querySelectorAll('input[type="file"]').forEach(i => {
    i.setAttribute('multiple', 'true'); i.multiple = true;
  });
  Array.from(document.querySelectorAll('[role="button"], button'))
    .filter(b => b.offsetParent)
    .find(b => /新增相片.*影片/.test((b.textContent||'').trim()))
    .click();
`

// Step 4 上傳 12 張 — 順序 1, 2, 3, ..., 12 嚴格按 paths 陣列順序
mcp__playwright__browser_file_upload paths=[
  "C:\\...\\01_xxx.png",
  "C:\\...\\02_xxx.png",
  ...
  "C:\\...\\12_xxx.png"
]
```

## 已試過全部失敗 ❌

| 方法 | 結果 |
|------|------|
| ❌ 檔名 0 padded `01_主題.png` ~ `12_主題.png` | 亂 |
| ❌ 檔名前綴 `5-12-01_xxx` / `第N篇12之01_xxx` | 亂 |
| ❌ `touch *.png` 同 mtime | 亂 |
| ❌ EXIF DateTimeOriginal 遞增(`2026:06:23 08:00:01` ~ `08:00:12`)用 piexif | 亂 |
| ❌ 刪除 PNG 內「Made with Google AI」IPTC/XMP metadata | 亂(這只跟 AI 標籤有關) |
| ❌ Playwright `browser_file_upload paths=[...]` 順序嚴格 1→12 | 亂 |

奇怪的是:
- **篇 1+2** 用 `01_主題.png` ~ `12_主題.png` 格式上稿 → **順序對** ✅
- **篇 4+5** 用同樣格式重新上稿 → **順序亂** ❌

兩者**檔名格式一樣**,行為卻不同。可能影響因素:
- 上傳時間段不同(篇 1 凌晨 1 點,篇 5 早上 7 點)
- 同一個 Playwright session 內第 N 次上傳 vs 第 1 次
- Cowork mount / sandbox 同步狀態

## 候選方案(待 Codex 驗證或提新方案)

### A. 一張一張 file_upload + 間隔 3 秒

每張 `setFiles([1 個檔案])` 後等 3-5 秒讓 Meta server 接收完成 → 下一張。

理論:Meta 依**接收完成順序**排,間隔可確保網路上載順序 = paths 順序。

★ 阿地還沒試,**可能是解**。

### B. Mobile user-agent

Playwright 加 `--user-agent="Mozilla/5.0 (iPhone; ...)"` 假裝行動裝置。

行動裝置 UI 排序邏輯可能跟桌面版不同(更穩定 / 按上傳順序排)。

### C. 上傳後 JS 強制拖動 DOM

```js
// 拉出 composer 內 12 張縮圖的 DOM 元素
const thumbs = document.querySelectorAll('.composer-thumb');
// 用 drag-drop event 模擬手動拖動到正確位置
// 細節需研究 Meta 的內部 state management
```

複雜但可能 work。

### D. 用 Chrome MCP 取代 Playwright

`mcp__Claude_in_Chrome__file_upload` 跑在真實 Chrome session,可能不同行為。

### E. 接受隨機 + 阿元手動拖
